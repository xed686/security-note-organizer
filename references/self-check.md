# 交付前自检清单

成稿后逐项对照。任何一项不满足,先改再交付。

## A. 读者视角(小白能不能听懂)
- [ ] 随机抽一个知识点:没有网安基础的人读完,能否用自己的话讲出"是什么、为什么、怎么做"?
- [ ] 每个术语第一次出现时,是否用中文把含义讲清楚?术语本身是否保留英文原词?
- [ ] 重点概念是否至少有一个类比,且类比能映射到真实机制?
- [ ] 有没有"显然""众所周知"这类默认读者已懂的措辞?

## B. 讲透(原理、思路、过程)
- [ ] 每个 🔴 知识点是否都有"为什么会存在(root cause)"?
- [ ] 每个步骤是否都回答了"做什么 / 为什么 / 得到什么 / 失败说明什么"?
- [ ] 每条命令或 payload 是否拆解到片段,并说明正常输出怎么读?
- [ ] 笔记里是否只有"步骤清单"而缺少 why?(有就要补)

## C. 联业务、能实战
- [ ] 每个 🔴 知识点是否挂了案例(真实事件或标注为"示例场景")?
- [ ] 案例是否交代了四件事:发生了什么 / 根因对应哪一环 / 业务后果 / 渗透测试者的启发?
- [ ] "实战怎么用"是否包含:触发线索、最小验证、结果判断、下一步?
- [ ] 有没有编造的 CVE 编号、公司名、金额?(必须为零)

## D. 诚实与可核实
- [ ] 所有由你补充的内容是否都有"🔎 补充"标注?
- [ ] 不确定的版本号、数字、参数是否放进了"待核实"清单,而不是写死?
- [ ] 原笔记中的错误是否被指出并解释,而不是悄悄改掉?
- [ ] 核实所用的来源是否都是非中国大陆来源?

## E. 结构与格式
- [ ] 是否输出为 `.md` 文件并通过 `present_files` 交付(用户未指定其他格式时)?
- [ ] 每个知识点是否标了相关度(🔴 / 🟡 / ⚪),详略是否与之匹配?
- [ ] 之前笔记已讲过的概念,是否只引用不重复,且引用的笔记真实存在?
- [ ] 是否有"方法论总览"和"自测"?
- [ ] 回复里是否只做了简短说明,没有把整篇笔记再贴一遍?

## F. 边界
- [ ] 开头是否写了一次"仅限授权环境 / 靶场 / CTF"?
- [ ] 有没有针对具体真实目标的攻击方案,或可直接投放的成型恶意程序?(必须为零)

---

## 常见失败模式(症状 → 对策)

| 症状 | 对策 |
|---|---|
| 笔记只是把原文重新排版 | 回到第 3 步,为每个知识点补 root cause 与三问 |
| 篇幅很长但没有重点 | 回到第 2 步重新分级,压缩 🟡 / ⚪ |
| 案例空泛 | 去 case-anchors.md 找真实案例,或改写为带业务名词的示例场景 |
| 读者分不清哪些是补充的 | 补上"🔎 补充"标注 |
| 命令讲了用法没讲原因 | 按"片段 / 作用 / 为什么需要"重写 |
