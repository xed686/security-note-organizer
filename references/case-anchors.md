# 案例锚点库

用于第 5 步:给重点知识点挂上真实业务案例。按漏洞 / 技术类型查找。

## 使用规则

1. 每个案例按四句交代:**发生了什么 → 根因对应笔记里哪一环 → 业务后果 → 渗透测试者的启发**。
2. 下表只给出**事件骨架**,细节(年份、规模、金额)写进笔记前,有联网能力时先核实,只用非中国大陆的来源(如 NVD、厂商安全公告、监管机构公告、英文权威媒体)。核实不了就只写事件性质,不写具体数字。
3. 找不到合适案例时,用"示例场景"代替,并明确标注,不要把虚构内容写成真实事件。
4. 案例是为了说明**为什么这个知识点值得学**,不要写成攻击教程。

## Web 应用类

| 类型 | 案例 | 根因(对应知识点) | 业务启发 |
|---|---|---|---|
| SQL Injection | Heartland Payment Systems 数据泄露(约 2008–2009 年披露),攻击入口为 SQL Injection,最终导致大量支付卡数据被窃取 | 用户输入被拼进查询;外部入口被攻破后进一步纵深渗透 | 一个注入点可能是进入内部网络的起点,不只是"读几条数据" |
| SQL Injection | TalkTalk 2015 年数据泄露,涉及 SQL Injection,后被英国监管机构处罚 | 老旧页面 / 遗留系统缺少输入处理 | 遗留系统和边缘业务是漏洞高发区,信息收集时要覆盖 |
| Stored XSS | Samy 蠕虫(MySpace,2005),利用存储型 XSS 在短时间内迅速扩散 | 用户内容未转义就输出给其他用户;脚本在受害者身份下执行 | XSS 的威力在于"以受害者身份做事",可用于蠕虫式传播 |
| SSRF | Capital One 2019 年事件,通过服务器端请求伪造访问云元数据服务获取凭据 | 服务端替用户发请求,且能访问内网 / 元数据地址 | 云环境里 SSRF 的危害远大于传统环境,要想到元数据服务 |
| 未授权 / 越权(IDOR) | Optus 2022 年事件,公开报道称因某个 API 缺少访问控制、标识符可枚举而导致大量用户信息暴露 | 接口没有校验"这个人能不能访问这条数据" | 测接口时要换 ID、换身份、去掉认证,验证每个资源的访问控制 |

## 组件与供应链类

| 类型 | 案例 | 根因 | 业务启发 |
|---|---|---|---|
| 已知漏洞组件未修补 | Equifax 2017 年事件,涉及 Apache Struts 漏洞(CVE-2017-5638),补丁发布后仍未及时修补 | 资产清单不全、补丁管理失败 | 信息收集阶段识别框架和版本,是渗透效率最高的步骤之一 |
| 日志组件远程代码执行 | Log4Shell(CVE-2021-44228),Apache Log4j 2 的 JNDI lookup 问题,日志里记录用户可控字符串即可触发 | 日志库对用户输入做了不该做的"解析" | "间接路径":任何会被记录、被解析的输入点都值得测试 |
| 命令注入 | Shellshock(CVE-2014-6271),Bash 环境变量处理缺陷,经 CGI 等途径远程触发 | 环境变量里的内容被当成命令执行 | 老组件藏在你想不到的地方,CGI、嵌入式设备要重点想 |
| 文件处理链 | GitLab CVE-2021-22205,上传的图片经 ExifTool 解析触发远程代码执行 | 上传后服务端的"二次处理"组件存在漏洞 | 文件上传的风险不只在后缀检查,还在服务端如何解析文件 |

## 权限与认证类

| 类型 | 案例 | 根因 | 业务启发 |
|---|---|---|---|
| 凭据泄露 / 无 MFA | Colonial Pipeline 2021 年事件,公开报道指向一个未启用多因素认证的 VPN 账号凭据 | 凭据复用 / 弱防护的远程入口 | VPN、远程管理入口是高价值目标;凭据类攻击成本低、回报高 |
| 弱口令 / 默认口令 | 大量物联网设备和管理后台因默认口令被批量控制(如 Mirai 僵尸网络) | 默认配置未修改 | 做完资产发现后,默认口令检查是必做项 |

## 系统与内网类

| 类型 | 案例 | 根因 | 业务启发 |
|---|---|---|---|
| Linux 提权 | Dirty COW(CVE-2016-5195),Linux 内核竞争条件导致本地提权 | 内核内存管理的竞争条件 | 拿到低权限 shell 之后,内核版本和已知提权漏洞是首要排查项 |
| Windows 提权 / 横向 | PrintNightmare(CVE-2021-34527),Windows Print Spooler 相关漏洞 | 默认开启的高权限服务暴露攻击面 | 域环境里,"不起眼的默认服务"可能成为提权和横向的突破口 |
| 内网横向移动 | NotPetya(2017),利用 EternalBlue(MS17-010)等漏洞结合凭据窃取在内网快速扩散 | 内网缺少分段、补丁缺失、凭据可被获取 | 内网渗透的核心是"凭据 + 网络可达 + 未修补服务"的组合 |

## 没有现成案例时:怎么写示例场景

写成下面这样,并加上"示例场景"字样:

> **示例场景**:某电商的"订单查询"接口 `/api/order?id=1001`,后端直接把 `id` 拼进 SQL。正常用户只会传自己的订单号,但攻击者把参数改成……(对应本笔记 1.3 的第 2 步)。后果是:任意用户的订单、手机号、地址可被读取,属于个人信息泄露,企业面临监管处罚和用户信任损失。

要点:

1. 选**业务名词**(订单、优惠券、发票、会员、支付回调),而不是抽象的"某系统"。
2. 明确写出**对应笔记里的哪一步**。
3. 说清**业务后果**:泄露了什么、谁受影响、企业会遇到什么问题。
