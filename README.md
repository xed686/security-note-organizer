# security-note-organizer

一个用于 **WorkBuddy / Claude 等 AI 助手的 Skill（技能包）**：把网络安全方向的课堂笔记、视频字幕、实验记录、文章资料，整理成**面向网安初学者的深度学习笔记**。

它的产出不是"排版更好看的原笔记"，而是一份**读完能听懂、并能在授权渗透测试里用起来**的笔记。

> 🌐 **本仓库提供中文版与英文版两套完整技能，均可独立安装**：
> **中文版**在仓库根目录（`SKILL.md` + `references/`），**英文版**在 `en/` 目录。
> 英文文档见 [README.en.md](./README.en.md)。

---

## 它解决什么问题

网安学习者手上的原始材料往往是碎的：只记了"做什么"，漏掉了"为什么"，更没有和真实业务挂钩。照着这种笔记，考试能背，实战却用不出来。

所以这个 Skill 要求整理出的笔记做到四件事：

| 目标 | 含义 |
| --- | --- |
| **听懂** | 每个概念有人话解释和类比，不堆术语 |
| **讲透** | 方法背后的原理、思路、**每一步的目的**都写出来 |
| **能用** | 能回答"我在真实目标上，什么时候想到它、怎么验证、下一步做什么" |
| **联业务** | 重点处挂接真实案例或典型业务场景，让知识落到具体的系统和损失上 |

写作视角是：**一位资深行业专家在给真正的初学者讲课**（费曼式）——假设对方没有任何前置知识，但很聪明，愿意认真听。

## 安装方法

### 方式一：直接用打包文件

下载 `security-note-organizer.skill`，放到技能目录下解压即可。

### 方式二：从本仓库克隆

**中文版**

```bash
# 用户级安装（所有项目可用）
git clone https://github.com/xed686/security-note-organizer.git \
  ~/.workbuddy/skills/security-note-organizer
```

**英文版**

```bash
git clone --depth 1 --filter=blob:none --sparse https://github.com/xed686/security-note-organizer.git \
  ~/.workbuddy/skills/security-note-organizer-en
cd ~/.workbuddy/skills/security-note-organizer-en && git sparse-checkout set en
```

> 若放到项目内使用，则克隆到 `{项目目录}/.workbuddy/skills/security-note-organizer/`。
> 英文版技能的 `name` 声明为 `security-note-organizer-en`，可与中文版同时安装而不会重名冲突。

## 使用方法

装好之后，直接把材料贴给 AI 助手即可，无需点名调用。典型触发说法：

- "网安笔记整理"
- "整理一下这份安全笔记"
- "把这节课整理成笔记"
- "帮我把这个漏洞讲懂并整理"

即使只贴素材、没说"整理"两个字，只要内容属于渗透测试、Web 安全、信息收集、内网、权限提升、漏洞原理、工具使用、Android 逆向等方向，也会自动走这套流程。

### 支持的输入类型

课堂笔记 / 视频字幕 / 实验（lab）记录 / 文章文档 / 截图 / 只有几个关键词。

输入很碎、很短时不会反过来追问一堆问题——能合理推断就直接产出，并把推断的部分明确标注出来。只有在**主题完全无法判断**时才会问一个澄清问题。

## 笔记长什么样

每个知识点按"讲透骨架"展开（核心是**每一步都有 why**）：

1. **是什么** —— 一句话定义 + 一个生活化类比
2. **为什么会存在** —— 漏洞或技术背后的 root cause（小白最缺这块，也是漏洞直觉的来源）
3. **怎么做** —— 分步骤，每步回答三件事：做什么、**为什么这么做**、做完得到什么
4. **业务里长什么样** —— 真实案例 / 典型业务场景
5. **实战怎么用** —— 何时该想到它 → 怎么验证 → 怎么判断结果 → 下一步做什么
6. **防御与检测视角** —— 知道防守方怎么修，才知道哪里容易漏
7. **易错点** —— 常见误区和排错线索

遇到命令、payload、工具参数，一律**拆解到每个片段**：这段是什么、起什么作用、为什么需要，并说明正常输出长什么样、怎么读。

### 相关度分级

不是所有知识点都讲一样深，会先判断实战相关度再决定篇幅，且**分级结果会写在笔记里**：

| 级别 | 判断标准 | 处理方式 |
| --- | --- | --- |
| 🔴 核心 | 直接出现在渗透流程里，或能培养"漏洞直觉"（SQL 注入、XSS、SSRF、文件上传、信息收集、权限提升、内网横向等） | 完整展开 7 个模块，配真实案例 |
| 🟡 辅助 | 支撑核心技能的基础知识（HTTP 协议细节、编码、常见中间件等） | 保留"是什么 / 为什么 / 怎么用"，案例可简写 |
| ⚪ 了解 | 与渗透实战关系较远（纯合规条文、冷门协议历史等） | 一段话讲清，并说明为什么优先级低 |

### 诚实标注

- 凡是**原资料里没有、由 AI 补充**的原理、案例、背景，统一用 `> [!note] 🔎 补充（非原笔记内容）` 标出，方便你核实。
- 不确定的版本号、CVE 编号、数字、参数**不凭印象写死**，核实不了的进"待核实"清单。
- 原笔记里明显有误的地方会指出来并给出正确做法，不会默默改掉。
- **绝不编造 CVE 编号、公司名、损失金额。**

## 已知注意事项

`SKILL.md` 第 7 步中，默认的笔记输出目录被写成了 `/mnt/user-data/outputs/`，这是 **Linux / 容器环境**的路径，在 Windows 上没有对应目录（往往会被解析到程序安装目录下，导致产出文件找不到）。

本仓库保留原始文件未作改动。如果你在 Windows 上使用，建议把该处改成工作区内的目录，例如：

```markdown
保存到当前工作区目录下的 `outputs/` 子目录；没有工作区时保存到 `C:\Users\<你的用户名>\WorkBuddy\outputs\`。
```

## 边界与底线

- 笔记面向**学习与获得授权的安全测试**。涉及攻击步骤的内容仅提醒一次"仅限授权环境 / 靶场 / CTF"。
- 用于讲解原理的 payload 和命令，保持在**课程与靶场教学**的粒度；不为具体未授权目标生成针对性攻击方案。
- 不写完整的、可直接投放的恶意程序（成型的勒索软件、免杀木马等）；需要说明原理时只讲机制和检测思路。
