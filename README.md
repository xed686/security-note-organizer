# security-note-organizer

一个用于 **WorkBuddy / Claude 等 AI 助手的 Skill（技能包）**：把网络安全方向的课堂笔记、视频字幕、实验记录、文章资料，整理成**面向网安初学者的深度学习笔记**。

它的产出不是"排版更好看的原笔记"，而是一份**读完能听懂、并能在授权渗透测试里用起来**的笔记。

> 🌐 **本仓库提供中文版与英文版两套完整技能，均可独立安装**：
> **中文版**在仓库根目录（`SKILL.md` + `references/`），**英文版**在 `en/` 目录。
> 英文文档见 [README.en.md](./README.en.md)。

---

## 它解决什么问题

网安学习者手上的原始材料往往是碎的：只记了"做什么"，漏掉了"为什么"，更没有和真实业务挂钩。照着这种笔记，考试能背，实战却用不出来。

所以这个 Skill 要求整理出的笔记做到四件事：

| 目标 | 含义 |
| --- | --- |
| **听懂** | 每个概念有人话解释和类比，不堆术语 |
| **讲透** | 方法背后的原理、思路、**每一步的目的**都写出来 |
| **能用** | 能回答"我在真实目标上，什么时候想到它、怎么验证、下一步做什么" |
| **联业务** | 重点处挂接真实案例或典型业务场景，让知识落到具体的系统和损失上 |

写作视角是：**一位资深行业专家在给真正的初学者讲课**（费曼式）——假设对方没有任何前置知识，但很聪明，愿意认真听。

下载 `security-note-organizer.skill`，放到技能目录下解压即可。

## 使用方法

装好之后，直接把材料贴给 AI 助手即可，无需点名调用。典型触发说法：

- "网安笔记整理"
- "整理一下这份安全笔记"
- "把这节课整理成笔记"
- "帮我把这个漏洞讲懂并整理"

即使只贴素材、没说"整理"两个字，只要内容属于渗透测试、Web 安全、信息收集、内网、权限提升、漏洞原理、工具使用、Android 逆向等方向，也会自动走这套流程。

### 支持的输入类型

课堂笔记 / 视频字幕 / 实验（lab）记录 / 文章文档 / 截图 / 只有几个关键词。

输入很碎、很短时不会反过来追问一堆问题——能合理推断就直接产出，并把推断的部分明确标注出来。只有在**主题完全无法判断**时才会问一个澄清问题。

## 笔记长什么样

每个知识点按"讲透骨架"展开（核心是**每一步都有 why**）：

1. **是什么** —— 一句话定义 + 一个生活化类比
2. **为什么会存在** —— 漏洞或技术背后的 root cause（小白最缺这块，也是漏洞直觉的来源）
3. **怎么做** —— 分步骤，每步回答三件事：做什么、**为什么这么做**、做完得到什么
4. **业务里长什么样** —— 真实案例 / 典型业务场景
5. **实战怎么用** —— 何时该想到它 → 怎么验证 → 怎么判断结果 → 下一步做什么 → **怎么证明影响**（用最小、无破坏的证据说明危害，决定漏洞定级）
6. **防御与检测视角** —— 知道防守方怎么修，才知道哪里容易漏
7. **易错点** —— 常见误区和排错线索

遇到命令、payload、工具参数，一律**拆解到每个片段**：这段是什么、起什么作用、为什么需要，并说明正常输出长什么样、怎么读。核心 payload 还会补两行：**环境前提**（语言版本、扩展、配置开关、目录权限）和**失败最常见的原因**——学习时最常卡的不是"不知道有这招"，而是"照着写了跑不出来"。

### 四档分级

不是所有知识点都讲一样深，会先按四档定级再决定篇幅，且**分级结果会写在笔记里**：

| 档位 | 含义 | 处理方式 |
| --- | --- | --- |
| 🔴 核心 | 高频、通用、能迁移，吃饭的家伙 | 完整展开 7 个模块，配真实案例；Web 漏洞类附代码层面对照 |
| 🟡 重要 | 实战会用到，但不是每天 | 写清是什么 / 原理 / 怎么做 / 实战怎么用；写明"用到时去哪查" |
| 🟢 了解 | 知道有这回事、能迁移思路 | 一小段概念 + 一句话可迁移思路；细节备查 |
| ⚪ 扫过 | 可遇不可求 / 冷门 / 已过时 | 一到两行，知道名字即可，不写步骤和代码 |

分级标到**具体知识点 / 小节**，不是整篇一个级别；每档后都带半句"该怎么对待"。

### 三种笔记类型

完整骨架（代码对照、真实安全事件、"实战怎么用"）是针对**漏洞类**笔记设计的。另外两类会换零件，而不是硬套：

| 环节 | 漏洞类 | 工具与架构类 | 方法论类 |
| --- | --- | --- | --- |
| "案例" | 真实安全事件 | **产品案例**（核对 README / 官方文档后写）或标注的示例场景 | 典型业务场景 + 示例场景 |
| 讲原理 | root cause + source/sink 代码对照 | 分层 / 结构图（谁调谁）+ 设计取舍 | 判断依据（什么信号走哪条） |
| "实战怎么用" | 触发线索 → 最小验证 → 影响证明 | **选型判断**：什么任务选它、什么任务别选 | 决策分叉 |

### 诚实标注

- 凡是**原资料里没有、由 AI 补充**的原理、案例、背景，统一用 `> [!note] 🔎 补充（非原笔记内容）` 标出，方便你核实。
- 不确定的版本号、CVE 编号、数字、参数**不凭印象写死**，按三级可信度处理：**实测（能在本机/靶场跑的，跑一遍）> 联网核实（非中国大陆来源）> 待核实清单**。实测会写清环境、命令与实际输出，"来源"里单列"实测"一行。
- 原笔记里明显有误的地方会指出来并给出正确做法，不会默默改掉。
- **绝不编造 CVE 编号、公司名、损失金额。**

## 落盘与索引（v1.1 起）

`SKILL.md` 第 7 步分两半：**7a 落盘与索引**、**7b 自检与交付**。写完之后不再只是"存成 md"，而是按宿主环境的既有约定落盘、并被索引找到：

1. 按主题放进**已有**的分类目录（确实没有合适的再新建，并告知你）。
2. 同目录已有 `00_`、`01_` 这类序号时**接着往下编**，保持同族命名。
3. 在该目录的 MOC 里补一行笔记清单，并把新笔记插进"主题线索"链的合适位置。
4. 新笔记写真实的上下篇与相关笔记；同时给**最相关的 1–3 篇旧笔记**回填双链。
5. 平台差异：Obsidian 写 `[[双链]]`，普通目录写相对路径；正文不再硬编码 claude.ai 的 `/mnt/user-data/outputs/`。

如果你确实在 claude.ai 里使用，把 7b 的落盘位置改成 `/mnt/user-data/outputs/`、再用 `present_files` 交付即可——这条现在是可选项，不再是默认假设。

## 边界与底线

- 笔记面向**学习与获得授权的安全测试**。涉及攻击步骤的内容仅提醒一次"仅限授权环境 / 靶场 / CTF"。
- 用于讲解原理的 payload 和命令，保持在**课程与靶场教学**的粒度；不为具体未授权目标生成针对性攻击方案。
- 不写完整的、可直接投放的恶意程序（成型的勒索软件、免杀木马等）；需要说明原理时只讲机制和检测思路。
